## ۳. پیاده‌سازی Endpoint حلقه (بخش ۳ تمرین)

- **لینک PR پیاده‌سازی Endpoint حلقه:** ‹لینک PR پیاده‌سازی ارزیابی ریسک در گیت‌هاب›
- **Endpointهایی که روی `main` کار می‌کنند:**
  - `POST /api/v1/risk-assessments` (ثبت و ارزیابی ریسک تراکنش — Endpoint حلقه با ذخیره‌سازی در PostgreSQL)
  - `GET /api/v1/risk-assessments` (دریافت فهرست ارزیابی‌های ثبت‌شده با صفحه‌بندی cursor)
  - `GET /api/v1/risk-rules` (دریافت فهرست قواعد فعال و غیرفعال ریسک از PostgreSQL)
  - `GET /api/v1/risk-statistics` (آمار کلی داشبورد ارزیابی ریسک)
  - `GET /health` و `GET /ready` (بررسی سلامت سرویس و اتصال پایگاه داده)

## ۴. Sequence Diagram (بخش ۶ تمرین)

**تعامل:** سرویس `S4-RSK` (به عنوان Consumer) در حین ارزیابی یک انتقال، برداشت‌های اخیر حساب مبدأ را از سرویس دفترکل `S2-LDG` (به عنوان Provider) استعلام می‌کند تا رفتارهای غیرعادی (مانند برداشت‌های مکرر و پشت‌سرهم) را تشخیص دهد. این نمودار شامل مسیر موفق و دو مسیر خطای «حساب پیدا نشد (404)» و «عدم پاسخگویی یا خطای 5xx از سمت S2» است.

```mermaid
sequenceDiagram
    participant S3 as S3-PAY
    participant S4 as S4-RSK (Consumer)
    participant S2 as S2-LDG (Provider)

    S3->>S4: POST /api/v1/risk-assessments
    S4->>S2: GET /api/v1/accounts/{id}/entries?direction=DEBIT&from=T
    alt success
        S2-->>S4: 200 items + next_cursor
        S4->>S4: evaluate rules using recent debits
        S4-->>S3: 201 decision APPROVE / REVIEW / REJECT
    else account not found
        S2-->>S4: 404 Problem Details NOT_FOUND
        S4->>S4: skip history rule, reason ACCOUNT_NOT_FOUND
        S4-->>S3: 201 decision REVIEW
    else no response or 5xx
        S4->>S4: timeout or 5xx, reason LEDGER_UNAVAILABLE
        S4-->>S3: 201 decision REVIEW
    end
