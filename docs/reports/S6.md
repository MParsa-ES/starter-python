## 1. Full Technical Architecture & Features Implemented

### A. Dynamic Rule Evaluation Engine (`assessments/engine.py` & `rules/selectors.py`)
* **Active Rule Filtering:** Queries active rules matching `enabled=True` and `effective_at <= evaluated_at` at the exact transaction timestamp.
* **Rule Type Handlers:**
  * **`AMOUNT_LIMIT`:** Validates single-transaction maximum bounds (`max_amount`) and daily cumulative totals.
  * **`BLOCKLIST`:** Evaluates source/destination accounts, destination IBANs, and national IDs against blocked identifier sets.
* **Severity Aggregation & Decision Logic:**
  * Evaluates all applicable rules and ranks decisions by highest severity:  
    $$\text{REJECT} > \text{REVIEW} > \text{APPROVE}$$
  * Default fallback decision is `APPROVE` when no risk rules match.
* **Immutable Audit Snapshots:** Persists `DecisionReason` records capturing immutable snapshots of `rule_id`, `rule_revision`, `rule_snapshot` (parameters, name, type), `code`, `message`, and `severity`.

### B. Idempotency Key Handling (`GEN-07`) (`assessments/models.py`, `assessments/views.py`)
* **Persistence Model:** Implemented `AssessmentCreateRequest` storing `(idempotency_key, actor, request_sha256, decision_id, response_status, response_body)`.
* **Race Condition Prevention:** Uses PostgreSQL `SELECT FOR UPDATE` row-level locks on the idempotency key record during evaluation.
* **Replay vs. Conflict Behavior:**
  * **Identical Replay:** Returns exact cached `201 Created` response body and headers when `(idempotency_key, actor, request_sha256)` matches.
  * **Conflict Rejection:** Returns `409 Conflict` (`IDEMPOTENCY_KEY_REUSED` RFC 9457 problem details) if an idempotency key is reused with a different payload or actor.
  * **Validation Safety:** Invalid requests returning `400 Bad Request` do not consume or store the idempotency key.

### C. Neighbor S2-LDG Ledger Integration (`integrations/ledger_client.py` $\rightarrow$ `assessments/services.py`)
* **Daily Debit Calculation:** Aggregates source account debits within the `Asia/Tehran` start-of-day boundary (`GEN-05`) up to the current transaction timestamp.
* **Paginated Client:** Iterates S2 ledger cursor pages until history is exhausted or threshold limits are surpassed.
* **Fail-Safe Resilience:**
  * **`ACCOUNT_NOT_FOUND` (404):** Safely flags the transaction as `REVIEW` with reason `ACCOUNT_NOT_FOUND`.
  * **`LEDGER_UNAVAILABLE` (Timeout / 5xx):** Intercepts network/service failures and escalates the decision to `REVIEW` without throwing an unhandled exception or breaking assessment evaluation.

### D. OpenAPI Contract & Serializer Synchronization (`contracts/openapi.yaml`, `assessments/serializers.py`)
* **Transfer Types:** Strict payload validation enforcing mutually exclusive transfer types:
  * `INTERNAL`: Requires `destination_account_id`, prohibits `destination_iban`.
  * `EXTERNAL`: Requires `destination_iban`, prohibits `destination_account_id`.
* **Numeric Bounds (`GEN-03`):** Configured `StrictPositiveInt64Field` with integer format `int64` and range $1 \le \text{amount} \le 9,223,372,036,854,775,807$ IRR.
* **Schema Validation:** Verified all REST responses against `contracts/openapi.yaml` using `assert_response_matches`.

### E. Test Suite Optimization & Environment Isolation (`conftest.py`, `assessments/tests.py`)
* **Ruff Fixes:** Resolved undefined symbol errors (`F821`) and import ordering issues (`E402`).
* **Neighbor URL Isolation:** Added an `autouse=True` fixture `_isolate_neighbor_urls` in `conftest.py` to prevent local `.env` values (`S2_LDG_BASE_URL=http://s2-ldg:8082`) from causing host network socket timeouts during local test execution.
* **Performance Gain:** Reduced pytest runtime from **160.8 seconds (with 7 failures)** to **\~10.0 seconds (with 100% pass rate)**.
