# ماتریس تست US-02: مدیریت قوانین ریسک

وضعیت: مبنای تست پیاده‌سازی حاضر. همه عملیات API به کاربر فعال در گروه `manager` نیاز دارند. `AMOUNT_LIMIT` نیازمند `max_amount` صحیح بین ۱ و `2^63-1` است. هر نوشتن موفق از سرویس، revision و تاریخچه را در یک تراکنش ثبت می‌کند.

| شناسه | سناریو | ورودی | نتیجه مورد انتظار | پوشش |
|---|---|---|---|---|
| R02-01 | ساخت معتبر | مبلغ ۱ یا `2^63-1` | موفق، revision ۱ و یک تاریخچه | unit و integration: `test_valid_amount_boundaries`, `test_valid_boundaries` |
| R02-02 | مرز نامعتبر | ۰، منفی، `2^63`، اعشاری، بولی، فاقد مبلغ | 400 یا خطای اعتبارسنجی؛ بدون داده جدید | `test_invalid_parameters_rejected_without_side_effects`, `test_invalid_amount_parameters_do_not_create_rule_or_history` |
| R02-03 | قالب پارامتر | آرایه یا null | خطای اعتبارسنجی | تست‌های نامعتبر بالا |
| R02-04 | اصلاح معتبر | revision فعلی و مبلغ جدید | 200، افزایش revision و ثبت before/after و actor | `test_create_update_and_read_audit` |
| R02-05 | رقابت کاربران | expected_revision قدیمی | 409 بدون تغییر یا تاریخچه تازه | `test_stale_and_invalid_patch_leave_original_unchanged` |
| R02-06 | اصلاح نامعتبر | مقدار نامعتبر یا actor در بدنه | 400؛ وضعیت ثابت می‌ماند | همان تست R02-05 |
| R02-07 | retry درخواست ایجاد | کلید و بدنه یکسان | همان 201 و همان پاسخ؛ فقط یک قانون و تاریخچه | `test_post_replay_and_conflict` |
| R02-08 | استفاده مجدد از کلید | همان کلید با بدنه یا کاربر متفاوت | 409 با کد `IDEMPOTENCY_KEY_REUSED`؛ پاسخ قبلی افشا نمی‌شود | `test_post_replay_and_conflict`, `test_same_key_cannot_leak_response_to_another_manager` |
| R02-09 | احراز هویت و دسترسی | بدون JWT یا بدون گروه manager | به‌ترتیب 401 و 403 | `test_auth_and_missing_rule`, `test_non_managers_are_denied` |
| R02-10 | قانون ناموجود | UUID ناشناخته | 404 برای ویرایش و تاریخچه | `test_auth_and_missing_rule` |
| R02-11 | صفحه‌بندی تاریخچه | limit=1 و cursor | نسخه‌ها به‌ترتیب نزولی بدون تکرار | `test_audit_cursor_pages` |
| R02-12 | شکست نوشتن تاریخچه | خطای ثبت تاریخچه | rollback تغییر قانون | `test_history_failure_rolls_back_existing_rule_update` |
| R02-13 | تغییر مستقیم تاریخچه در PostgreSQL | UPDATE یا DELETE | خطای دیتابیس | `test_database_rejects_history_update_and_delete` |
| R02-14 | قانون قدیمی بدون تاریخچه | تغییر قانون موجود با revision ۳ | فقط نسخه ۴ و snapshot قبل/بعد ثبت می‌شود | `test_existing_rule_gets_history_only_when_updated` |
| R02-15 | دو درخواست هم‌زمان | دو POST با کلید یکسان | دو پاسخ یکسان و تنها یک قانون | `test_concurrent_post_same_key_creates_one_rule` |
| R02-16 | دو ویرایش هم‌زمان | هر دو با revision یکسان | یک 200 و یک 409؛ فقط یک نسخه جدید | `test_concurrent_patch_allows_only_one_revision` |

محدودیت: ORM و SQL مستقیم روی خود RiskRule هنوز می‌توانند مسیر سرویس را دور بزنند. trigger تاریخچه، UPDATE/DELETE معمولی را منع می‌کند اما مالک دیتابیس می‌تواند trigger را غیرفعال کند و TRUNCATE نیز حفاظت نشده است؛ نقش‌ها و مجوزهای جداگانه برای استقرار واقعی لازم‌اند.
