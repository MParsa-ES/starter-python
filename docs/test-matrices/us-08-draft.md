# پیش‌نویس ماتریس US-08: توضیح‌پذیری تصمیم

این پیش‌نویس مشخصات نهایی استوری نیست. در مدل فعلی `DecisionReason` فیلدهای code، message، rule_id، rule_revision و rule_snapshot وجود دارند؛ وجود این مدل به‌تنهایی اثبات کامل بودن API یا برآورده‌شدن استوری نیست. endpoint، نقش‌های مجاز، قرارداد پاسخ، تعداد علت‌ها و نحوه نمایش داده حساس باید با تیم توافق شوند.

## RSK-37: شروع کار

آزمون‌های `assessments/test_explanation_serialization.py` قرارداد فعلی نمایش دلیلِ دارای شناسه و نسخه و snapshot قانون و نیز دلیل پیش‌فرض بدون قانون را پوشش می‌دهند. این آزمون‌ها نقطهٔ شروع بوده‌اند؛ جزئیات API و محدودیت‌های پیاده‌سازی جدید در بخش بعد آمده است.

## پیاده‌سازی پیشنهادی RSK-37

مسیر `GET /api/v1/risk-assessments/{decision_id}/reasons` برای نقش‌های فعال `manager`، `operator` و `analyst`، دلایل ثبت‌شده را به ترتیب ایجاد با `limit` و `cursor` برمی‌گرداند. هر دلیل شامل `code`، `message`، `rule_id` و `rule_revision` است. پارامترها و snapshot قانون در این مسیر منتشر نمی‌شوند؛ متن پیام ثبت‌شده نمایش داده می‌شود و سیاست محتوای آن باید در بازبینی امنیتی تیم تأیید شود. شناسهٔ ناموجود 404 و دسترسی غیرمجاز 401 یا 403 برمی‌گرداند. صفحهٔ `/explanations` از همین API استفاده می‌کند. نقش‌ها و حذف snapshot از پاسخ مطابق الگوی فعلی تاریخچه و انتخاب این پیاده‌سازی هستند و باید در بازبینی تیم تأیید شوند. برای تاریخچهٔ تصمیمات دستی از API استوری ۶ استفاده می‌شود؛ این مسیر دلایل ارزیابی اولیه را نمایش می‌دهد.
